# Contact Kernel

自研 CPU 接触内核。它是 Phase 1 中 Isaac Sim 动力学与接触报告的解耦替代品，只导入标准库：不导入仿真器、不导入 `tactile_contract`、不导入任何层模块。

因此它可以被测试直接驱动、被五层闭环驱动，或被将来的前端驱动，而不引入平台依赖。规格到内核配置的转换在 `virtual_reality/` 完成，内核帧到契约记录的转换在 `interaction/` 完成。

## 模块职责

| 模块 | 输入 | 输出 |
| --- | --- | --- |
| `spec.py` | 形状、时间、网格、采样、求解与驱动选择 | `KernelConfig`，含范围校验 |
| `geometry.py` | 位姿、形状 | 间隙、法向、切向基、局部坐标、网格索引、扫过单元、圆盘覆盖 |
| `solver.py` | 命令、质量、运动状态 | 法向冲量、更新状态、逐子步诊断 |
| `tracking.py` | 接触点、前帧轨迹 | Point ID、Cell、Patch ID、分裂合并、Episode |
| `kernel.py` | 以上全部 | `KernelFrame`：每物体对的接触解、三层面积、守恒残差 |

## 当前范围

K1 只求解一个转动锁定的球形探头对一个固定长方体顶面，单接触点，零摩擦，零恢复系数。这不是通用刚体求解器：盒形探头、多接触点、堆叠和任意网格会显式抛 `NotImplementedError` 并指向对应里程碑，而不是静默近似。

守恒与语义约定：

- 法向冲量为非负；输出力等于输出区间内的冲量之和除以输出步长。
- 数值穿透由几何投影消除，投影量单独记录，从不折算成接触力。
- 网格是**输出**离散化。改变网格不改变动力学。
- 面积分三层同时输出（`point_occupancy`、`swept_path`、`geometric_footprint`），模型接触面积在 K4 之前恒为 `null`。
- 求解器做了什么和采样报告了什么分开记录：低于采样阈值或滑出顶面的接触带原因字符串，而不是消失。

## 精度与性能

CPU 双精度，纯 Python 浮点。内循环使用标量与元组；JSON Schema 校验和 JSONL 写入只在记录边界发生，不在每个子步发生。确认性能瓶颈后再考虑编译优化或 Warp 后端，迁移时需要比较数值精度、驱动依赖和数据传输开销。

## 测试

```text
cd "Phase 2"
.venv/Scripts/python.exe -m pytest contact_kernel/tests -q
```

`tests/` 覆盖解析几何边界、网格策略、圆盘覆盖收敛、接触起止、保持力的驱动语义、穿透修正、子步细化不变性、点与 Patch 身份稳定性、分裂合并事件和 Episode 关闭。
