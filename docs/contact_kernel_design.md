# 接触内核设计与 Step 6 复现路线

本方案以 CPU 可独立运行的局部接触内核为主线。Phase 2 首先复现 Step 6 的刚体交互行为，再增加材料相关的接触区域、压力和形变。Unity 负责可替换的场景编辑与显示。4070 或租用 GPU 用于后续批处理和加速。

本文件定义实施顺序和验收范围。它不代表接触求解器、Unity 适配器或材料闭环已经实现。

## 复现对象

Phase 1 的 `scripts/step6_3.py` 使用半径 0.12 m、质量 0.05 kg 的动态球形探头，参考方块边长 0.50 m，物理步长为 1/60 s。严格回归将参考体固定并锁定探头旋转。每帧先设置探头速度，再执行物理步进，随后读取接触冲量并除以步长得到帧平均力。

`scripts/step6_5.py` 使用两个动态长方体探头，每个质量为 0.08 kg，接触同一固定表面。该用例要求多点、多网格、多 Patch、稳定 ID、释放清除和力守恒。只支持球面的内核不足以复现这项用例。

复现的首要目标是控制和数据语义一致：接近、保持、滑动、释放、力控调节、严格运动学、Point/Cell/Patch/Episode 和稀疏密集回放。跨求解器接触点数量、点 ID 和瞬时峰值不作为逐位相同的目标。

## 接触区域与轨迹分开

Phase 1 的实际逻辑为：

```text
当前帧接触点 -> 当前帧 Cell -> 当前帧 Patch
                       跨帧匹配 -> 轨迹与 Episode
```

轨迹是接触随时间变化的记录，无法恢复单帧真实接触面积。刚体接触流形中的点用于动力学约束，点数和位置受到接触生成及缓存策略影响。PhysX 的 PCM 会复用前帧接触点，因此不能把接触点密度解释为压力采样密度。[PhysX 接触生成说明](https://nvidia-omniverse.github.io/PhysX/physx/5.1.3/docs/AdvancedCollisionDetection.html)

区分以下面积：

| 面积 | 来源 | 使用边界 |
| --- | --- | --- |
| 占格代理面积 | 当前帧有接触点的网格面积之和 | Step 6 兼容输出，随输出分辨率变化 |
| 几何重叠区域 | 当前姿态下几何形状的交叠或投影 | 不自动等于弹性接触区域 |
| 模型接触面积 | Hertz、弹性地基或其他接触模型 | 携带模型、假设和估计标识 |
| 累计扫过面积 | 一段时间内接触区域的并集 | 轨迹覆盖分析，不能代替瞬时面积 |

## 计算架构

```text
场景配置 + 前帧状态 + 控制命令
        ↓
接触候选与局部间隙
        ↓
刚体冲量模式 / 柔顺接触模式（二选一）
        ↓
更新物体状态 + 接触解
        ↓
Point 兼容输出 / 连续区域与压力场
        ↓
守恒栅格化 -> Cell -> Patch -> Episode
        ↓
InteractionState + 原始证据 + ExperimentManifest
```

模块职责如下：

| 模块 | 输入 | 输出 |
| --- | --- | --- |
| Geometry Query | 位姿、形状、速度 | 接触候选、间隙、法向、切向基 |
| Contact Solver | 候选、质量、运动状态、材料参数 | 冲量或力、接触区域、更新状态 |
| Field Rasterizer | 点、接触区域、压力 | 面积覆盖率、Cell 力和压力 |
| Patch Tracker | 当前帧 Cell、前帧轨迹 | Patch ID、分裂合并关系、Episode |
| Controller/Runner | 前帧观测、控制配置 | 下一步命令、固定仿真时钟 |
| Recorder/Validator | 求解结果与配置 | 标准记录、证据、验收报告 |

内循环使用数值数组。JSON Schema 校验和 JSONL 写入在记录边界执行，避免每个网格、每个子步都执行 JSON 序列化。

## 刚体冲量模式

首版支持固定平面或有限方块顶面、球形探头、轴向对齐的平底长方体探头和多探头。首批验收范围保持探头旋转锁定，不扩展到任意网格、关节、堆叠或自碰撞。

每步执行：

1. 按 Step 6 语义设置探头速度命令。
2. 计算重力作用后的自由速度。
3. 检查当前或预测步末间隙，建立非穿透约束。
4. 求解非负法向冲量，按摩擦锥约束切向冲量。
5. 更新速度和位置，并单独记录数值穿透修正。
6. 用输出时间窗内的冲量总和除以输出步长生成帧平均力。

对于已经处于固定平面上的单个锁旋转探头，忽略恢复系数和穿透修正，法向冲量的简化参考为：

```text
v_free_n = v_command_n + g_n * dt
J_n = max(0, -m * v_free_n)
F_n_frame = J_n / dt
```

该式只适用于上述单接触情形。离开表面且不会在本步触碰时不施加冲量。多点约束需考虑共享刚体状态，不能让每个接触点都独立施加整物体所需冲量。

起步使用单接触解析解。平底多点用小型投影迭代或具有明确对称假设的分配规则，并记录实现方法。静摩擦与滑动摩擦通过切向冲量限制处理，零速时不归一化零向量。

Step 6 的 `set_linear_velocity` 语义会影响力与时间步长的关系。改变控制周期或将速度命令在每个子步重新写入，会改变系统。兼容测试先保持 60 Hz 控制与输出，内部子步单独记录。

## 柔顺接触模式

### 球面与 Hertz 基线

先建立光滑、无黏附、准静态、小变形、近似弹性半空间条件下的球面基线。对于球面相对平面的总弹性压入量 δ、球半径 R 和等效模量 E*：

```text
a = sqrt(R * δ)
A = π * a²
F_n = (4/3) * E* * sqrt(R) * δ^(3/2)
p(r) = 3 F_n / (2 π a²) * sqrt(1 - r²/a²),  0 <= r <= a
1/E* = (1-ν1²)/E1 + (1-ν2²)/E2
```

δ=0 时单独返回零力和零面积，避免除零。材料参数不取自 PhysX 为防穿透引入的接触偏移量。Hertz 模型适用范围和法向/切向弹性接触建模可参考 [Itasca Hertz 文档](https://docs.itascacg.com/itasca900/common/contactmodel/hertz/doc/manual/cmhertz.html)。

几何球体插入平面的截面半径 `sqrt(2Rδ-δ²)` 与 Hertz 接触半径不同。二者不能混用。有限厚度软体、大形变、边缘接触、近不可压缩材料和黏附需要后续单独模型。

### 弹性地基与材料响应

局部高度场的弹性地基模型适合生成二维响应。每个材料网格具有独立压缩量与内部状态，可采用：

```text
p_i = max(0, K_i * δ_i + C_i * δ_dot_i)
F_i = p_i * A_i
```

其中 `K_i` 的单位为 Pa/m，`C_i` 为 Pa*s/m。若使用单元弹簧刚度 N/m，必须随面积缩放。否则细化网格会人为增加总刚度。

Hertz 与弹性地基是不同物理假设，不叠加使用。先让各自满足解析参考或网格收敛，再比较适用范围。Standard Linear Solid 的内变量按材料单元独立保存，固定在物体材料坐标系，不绑定不断移动的接触点 ID。

### 接触面模型的后续选择

SDF 提供间隙、法向和碰撞候选，本身不产生压力或真实形变。任意形状支持可在解析形状之后增加局部 SDF。

Drake 的 hydroelastic 方法可作为接触区域与压力分布的外部对照。该方法并不等同于有形变自由度的 FEM，也不自动提供粘弹性历史。[Drake Hydroelastic 指南](https://drake.mit.edu/doxygen_cxx/group__hydroelastic__user__guide.html)

## 两种模式之间的边界

刚体模式的力来自约束冲量。柔顺模式的力来自材料接触模型。一个接触对、一个时间步只选择一个权威动力学求解器。

如果用刚体总力重建 Hertz 压力分布，需要额外假定材料参数，并标记为压力估计。该估计不能再次作为额外接触力叠加到刚体求解器。

五层是职责划分，层 2 和层 3 的物理计算可以在同一步内耦合：几何候选传给材料模型，材料模型返回接触力和状态，求解器更新动力学，最终封装 `InteractionState`。材料层不应在已经包含材料响应的状态上重复计算同一份形变。

## 守恒栅格与 Patch

提供两种明确区分的输出：

- `point_occupancy`：保持 Step 6 当前帧接触点占格的定义。
- `model_footprint`：将模型接触区域积分到网格。

对网格单元 C_i 和模型接触区域 Ω：

```text
α_i = area(C_i ∩ Ω) / area(C_i)
A_contact = Σ α_i * area(C_i)
F_i = ∫_(C_i ∩ Ω) p(x,y) dA
```

矩形与网格交叠使用几何裁剪。圆形和一般局部区域使用子单元积分，并通过提高积分精度验证收敛。只处理接触附近的 ROI。面积来自覆盖率，不能通过随意增加点数改变。

Cell 压力第一版统一为整格平均值 `F_i / area(C_i)`，避免部分覆盖时分母不一致。真实接触区域上的均值和峰值使用单独定义。网格峰值与解析点峰值分开记录。

Point 到 Cell、Cell 到 Patch 都应守恒总力。对以后开放旋转的用例，还需比较关于指定参考点的力矩。保留几何中心和力加权中心的区别。

先按物体对和表面 ID 分组，再提取连通区域。基线兼容模式沿用四邻域。模型区域模式不能通过膨胀或凸包填充跨越真实空隙。跟踪使用位移预测、区域重叠和确定性匹配，记录分裂、合并、开始和结束事件。

轨迹历史和材料残余形变可在释放后保留，当前接触 mask 和接触力必须清除。临时丢帧的轨迹延续策略不能伪造当前接触。

## 时间与算力

仿真时间、输出时间和墙钟耗时分开。较慢硬件可以用更长墙钟时间完成相同的固定仿真步，不能靠增大物理步长掩盖性能不足。柔顺高刚度模型必要时使用更小子步或隐式积分。

| 设备 | 首要用途 | 约束 |
| --- | --- | --- |
| CPU | 解析几何、小型刚体求解、材料单元、所有基础回归 | 作为必须通过的参考后端 |
| 本机 4070 | Unity 显示、较大二维场和参数批处理 | 根据实际分析结果决定是否迁移 GPU |
| 租用 5090 或更高算力 | 多实验并行、较大网格、离线高保真对照 | 不成为核心验收前置条件 |

起步使用 Python 和 NumPy 的 CPU 双精度实现。确认性能瓶颈后再选择编译优化或 Warp 后端。Warp 提供 CPU 与 CUDA 执行方式，但迁移仍需比较数值精度、驱动依赖和数据传输开销。[Warp 基础文档](https://nvidia.github.io/warp/stable/user_guide/basics.html)

GPU 型号不只是速度差异，还影响显存容量、驱动与数据类型性能。内核应明确内存上限、可支持精度和 CPU 回退，不承诺任意规模只需增加等待时间即可完成。

离线复现允许慢于实时。真实执行器闭环需要在时限内运行本地控制，慢速材料求解只更新参数或目标，不能直接阻塞驱动回路。

## Unity 接入

第一阶段 Unity 只编辑场景、提供轨迹并显示返回状态。接触内核采用独立进程或可替换库。涉及测试的物体只有一个动力学状态所有者，避免 Unity PhysX 和自研求解器同时修正位置并施加反力。

Unity 内置 3D 物理也是 PhysX 的集成，迁移前端本身不等于接触内核解耦。[Unity 物理说明](https://docs.unity3d.com/6000.0/Documentation/Manual/PhysicsOverview.html)

接入时显式转换左右手坐标、轴方向、单位和旋转，不根据字段名称猜测。物理步长保持固定，渲染插值独立。Unity 官方也要求手动模拟使用固定步长，避免帧率波动改变模拟结果。[Physics.Simulate](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Physics.Simulate.html)

## 契约前置修正

当前 Phase 2 的契约是可用骨架，但尚不足以证明完整 Step 6 兼容。实施内核前补齐：

1. `ExperimentManifest.conditions` 的嵌套 Schema，明确形状、初始状态、重力、摩擦、恢复系数、单位和坐标变换。
2. 记录驱动语义、控制器配置、物理子步、输出窗口、接触偏移量和求解器版本。力控命令由反馈生成，不能强制声明成预先已知的结果轨迹。
3. 当前 `validate_run` 只接受一个物体对的连续流。多探头采用每物体对独立流加运行索引，Patch 细节保留在独立证据流，不把多个法向强行平均成一个平面状态。
4. 增加接触区域方法、网格原点与覆盖定义、Patch 生命周期证据。区分整格压力、接触区压力和数值峰值。
5. 分开物理输入摘要与求解/离散化配置摘要。当前完全相同的条件摘要门槛会阻止有意改变时间步或网格的收敛比较，需要显式 comparison profile。
6. 补齐非法嵌套参数、二维场、JSONL/NPZ 往返、产物哈希、丢帧和多流一致性的测试。当前 5 个测试只覆盖部分基础行为。

涉及含义或不兼容结构变化时新增版本或独立附件契约。Phase 1 不回写改动。

从冻结代码保留的门槛包括保持接触覆盖率不低于 95%、滑动速度在 0.05±0.01 m/s 内的样本占比不低于 90%、1 N 力控在 ±0.05 N 内的滑动样本占比不低于 90%、多 Patch 稳定覆盖不低于 90%、Point/Cell 力误差不超过 1e-5 N，以及 32/64/128 网格下峰值总力相对离散不超过 10%。各项仍以对应 Step 6 脚本为准。

这些是行为与守恒门槛，不是和 PhysX 数值完全一致的证明。两类测试分开执行：相同输入命令用于隔离求解器差异，相同闭环控制器用于验证功能。闭环下两后端产生不同命令是允许观察的结果，不能强行要求输出轨迹相同。

模型区域新增独立验收：Hertz 解析关系、压力积分与总力一致、边界裁剪、网格与时间步收敛、无接触力清除、材料松弛恢复，以及 CPU/GPU 容差内一致。

## 当前结论

K0 已完成来源参数清单、运行时未解析标记和单探头 CPU 参考输入。

K1 已实现。接触内核解耦到 [`contact_kernel/`](../contact_kernel)（只依赖标准库），五层边界记录与固定顺序驱动器在 [`tactile_contract/pipeline.py`](../tactile_contract/pipeline.py)，各层实现在对应层目录。单球探头、固定顶面、解析法向冲量、速度命令、严格运动学、Point/Cell/Patch/Episode、三层面积输出和确定性回放全部就位，九项验收门槛通过。运行时字段带三分类裁决，不支持的取值在加载期拒绝。实现细节、与 Step 6 的两处显式差异，以及 K1 未做的事，见 [`k1_single_probe_rigid.md`](k1_single_probe_rigid.md)。

下一步实现 K2。开发机作为默认环境，CPU 作为默认求解后端。先恢复 Step 6 的刚体控制与数据行为，再以模型接触区域替代对材料实验不充分的点占格面积。租卡、Unity 和完整 FEM 都不作为该内核的前置依赖。
