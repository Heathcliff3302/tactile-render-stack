# 触觉渲染栈推进总览（跨阶段）

本页回答一个问题：**相对最初的设想，现在走到哪了。**

上位愿景见根目录 [`触觉渲染系统总体构想与初期项目路线.md`](../../触觉渲染系统总体构想与初期项目路线.md)。Phase 1 的逐步记录见 [`Phase_1/.../docs/step_record/00-项目总推进.md`](../../Phase_1/isaacsim-rigid-contact-pipeline/docs/step_record/00-项目总推进.md)。本页不复述它们，只做跨阶段对照。

> **口径。** 每个结论标注三种状态之一：**已验证**（有可复现的运行证据或测试）、**已实现未验证**（代码在，但缺独立验证）、**未做**。不使用"大致完成"这类无法反驳的说法。
>
> **更新规则。** 每个里程碑收口时更新，追加到末尾的更新记录，不覆盖历史判断。数字来自代码与运行产物，不凭印象填写。

## 一、最初设想的三件事，现在各自什么状态

当初的设想是三件事：**冻结协议、解耦触觉核、引入后续各层形成闭环**。三件事的推进很不均匀，分开说才有意义。

| 设想 | 状态 | 已经做到的 | 还差的 |
| --- | --- | --- | --- |
| **冻结协议** | 关键一条已冻结 | 层 2 边界 `InteractionState v2` 带版本 Schema 并哈希绑定；`ExperimentSpec v1`、`ExperimentManifest v1` 同样冻结 | 层 3/4/5 的记录仍是进程内接口，不是带版本契约 |
| **解耦触觉核** | 架构完成，等价性未验证 | Phase 2 对 Isaac Sim 的 import 为 **0**；`contact_kernel/` 1825 行仅依赖 `math` 与 `dataclasses`；250 个测试不需要仿真器或 GPU | 没有 Isaac Sim 适配器，没有数值等价结论 |
| **各层闭环** | 结构闭环，内容未闭环 | 五层每个控制步都必须产出记录，缺失抛异常；轨迹与力控两种模式都走完全链路 | 层 3 是透传、层 4 只有一个通道、层 5 没有硬件 |

**一句话概括：管道通了，内容还薄。**

这句话不是谦辞，而是对照最初路线得出的结论。原始路线的"阶段一"定义是：

> 单指尖、**三种**虚拟材料、法向力与**振动**双输出的触觉解算器。

现在是：单指尖、**一种**刚体材料（且层 3 为透传，不产生独立材料响应）、**一个**法向力通道。Phase 1 与 Phase 2 实际建成的，是这个目标**下面的那层地基**——接触检测、证据契约、五层骨架、验收护栏。地基比原计划扎实得多，但"三种材料 + 振动"这件原本定义阶段一的事，一项都还没开始。

## 二、五层链路：两个阶段各自推进到哪

```text
层 1 虚拟世界状态   Phase 1 ███████░░░  Phase 2 ██████████
层 2 接触检测       Phase 1 █████████░  Phase 2 ██████████  ← 边界已冻结
层 3 材料响应       Phase 1 ░░░░░░░░░░  Phase 2 ██░░░░░░░░  ← 仅透传基线
层 4 标准触觉目标   Phase 1 ░░░░░░░░░░  Phase 2 ██░░░░░░░░  ← 仅法向力单通道
层 5 执行器逆模型   Phase 1 ░░░░░░░░░░  Phase 2 ███░░░░░░░  ← 无硬件，模型化测量
```

| 层 | Phase 1 交付 | Phase 2 交付 | Phase 2 的诚实边界 |
| --- | --- | --- | --- |
| 1 世界状态 | 固定场景、速度轨迹、PI 力控、固定时钟 | 同上并加：运行时字段三分类裁决、命令出口限幅、`max_duration_s` 硬终止、力控三道加载期护栏 | 单球探头、转动锁定、固定平面 |
| 2 接触检测 | Point→Cell→Patch→Episode、稠密场、32/64/128 网格、多 Patch、自动回归 | 相同表示 + **带版本契约** + 面积四层分标 + 采样阈值可见性 | 面积是占格代理，`physical_contact_area_m2` 全程 `unavailable` |
| 3 材料响应 | 未做 | `RigidBaselineMaterial`，`status = passthrough` | 刚体冲量模式下内核已是唯一权威求解器，层 3 再算一次就会重复计入。刚度/阻尼为 `null` |
| 4 触觉目标 | 未做 | `NormalForceTargetStage`，1 个通道 | 振动与温度字段为 `null`，不是零 |
| 5 执行器 | 未做 | 单轴命令路径、逆模型、饱和、延迟、看门狗 | `status = modelled_not_measured`，未接硬件 |

Phase 1 把层 2 做到了可冻结；Phase 2 把层 2 的**边界**冻结，并把层 3–5 从零变成"有记录、有状态标记、但内容很薄"。

## 三、协议冻结：冻了哪些，没冻哪些

| 契约 | 版本 | 状态 | 作用边界 |
| --- | --- | --- | --- |
| `InteractionState` | v2 | **已冻结**，JSON Schema + 哈希绑定 | 层 2 → 层 3，这是"开放边界"所在 |
| `ExperimentSpec` | v1 | **已冻结** | 运行前规格，含阈值台账与字段裁决 |
| `ExperimentManifest` | v1 | **已冻结** | 绑定条件、观测量定义、每个产物的 SHA-256 |
| `MaterialResponse` | — | 未冻结 | 进程内接口，K4 升版 |
| `TactileTarget` | — | 未冻结 | 进程内接口，K5 升版 |
| `ActuatorCommand` / `Measurement` | — | 未冻结 | 进程内接口，K5 升版 |

**为什么只冻结了层 2 这一条就算关键。** Phase 2 的全部意义是把层 2 变成一条开放边界：任何接触数据来源，只要能产出通过校验的逐帧记录，层 3 到层 5 就无需改动地跑下去。这条边界冻结之后，换后端不再是改架构，而是写一个适配器。

层 3/4/5 刻意**不**提前冻结：现在没有真实材料模型、没有真实执行器，冻出来的契约会是对想象的承诺。它们在 K4/K5 升版——那时才有东西来定义什么必须保持稳定。

Phase 1 有 **0** 个 JSON Schema，证据格式是 CSV 列约定。这是两个阶段之间最大的性质差异：从"约定"变成"机器强制"。

## 四、解耦触觉核：可核验的部分与未核验的部分

**已验证（可直接复算）**

| 指标 | Phase 1 | Phase 2 |
| --- | --- | --- |
| 导入 Isaac Sim 的源文件数（`omni.` / `isaacsim` / `pxr` / `carb`） | 12 | **0** |
| JSON Schema 数 | 0 | 3 |
| 测试函数数 / pytest 收集数 | 22 | 230 / **250** |
| Python 行数 | 10,953 | 10,642 |
| 跑测试是否需要仿真器或 GPU | 需要 | **不需要** |

`contact_kernel/` 模块本体 1825 行（另有 499 行测试），全部 import 只有 `math` 与 `dataclasses`：不导入仿真器、不导入契约包、不导入任何层模块。Phase 2 中唯一出现 `isaacsim` 字样的位置是 `scenarios/build_k0.py` 里的一个**路径字符串**，用于从 Phase 1 源码提取参数并记录哈希——不是 import。

行数几乎相同但性质不同：Phase 1 的一万行里有仿真器绑定，Phase 2 的一万行里有契约、护栏和验收台账。

**未验证**

与 Isaac Sim 之间目前**只有行为与守恒门槛，没有数值等价结论**。未解析的 PhysX 有效运行时参数采集完成之前，两者只做趋势比较。解耦作为架构成立，作为"同一物理的两种实现"尚未证明。

这不是待办清单上的一项普通工作，而是"解耦"这个词能否成立的判据。目前的准确表述是：**解耦已完成，等价未验证。**

## 五、闭环：结构通了，内容还薄

`FiveLayerLoop` 的生命周期为 `initialized → running → completed | aborted(reason)`，只有层 1 能结束运行且必须说明原因。每个控制步按固定顺序穿过五层，**任何一层缺失记录都抛异常，不静默跳过**。

两种控制模式都走完全链路：

```text
K1 轨迹模式   472 帧 / 7.87 s    十项门槛全通过
K2 力控模式   797 帧 / 13.28 s   十三项门槛全通过
```

所以"闭环"在结构意义上成立：输入到执行器命令与测量，每一步都有记录、有单位、有模型标识、有状态标记。

但内容意义上远未成立，三处都已在产物里显式标注（以下字段取自 `experiments/runs/k2-force-cpu/` 的首帧）：

| 层 | 产物 | 标注 |
| --- | --- | --- |
| 3 | `material_response.jsonl` | `status = "passthrough"`，`stiffness_n_per_m = null`，`damping_ns_per_m = null` |
| 4 | `tactile_target.jsonl` | `channels = ["normal_force"]`，`vibration_amplitude = null`，`temperature_c = null` |
| 5 | `actuator_io.jsonl` | `status = "modelled_not_measured"`，`model_id = "single_axis_ideal_first_order_v0"` |

这三个标记不是注释，是下游必须读的字段：`null` 与 `0` 在这套契约里语义不同，写零会被当成真实测量。

对照原始路线的阶段三（"连接单一或双通道执行器 → 传感器实测输出 → 人体辨识结果"），层 5 的**代码路径**已经建好（命令、逆模型、饱和、延迟、看门狗都是真实实现），缺的是硬件。K5 只需替换传递模型——这是个有价值的位置：接硬件时不需要重写这一层。

| 里程碑 | 状态 | 证据 |

| K4 模型接触区域 | 未做 | Hertz、弹性地基、压力场、守恒栅格 |
| K5 Unity 与五层闭环 | 未做 | 场景输入、执行器标定、误差与延迟报告 |

K2 的交付物台账由 `validation.milestone_status` 机器登记，运行报告里是两个独立字段：

```text
run_acceptance_passed  true     这一次运行的全部门槛都发出且通过
milestone_complete     false    还缺 isaac_sim_parity
sub_milestone          K2-A     CPU 参考后端，单场景
```

**单次运行通过不等于里程碑完成**，这一条由代码强制而非文档提醒。

Phase 1 在 Step 6.4 交付的 13 通道稠密场曾是 Phase 2 的一处能力回退，现已补齐：通道名与顺序完全沿用 Phase 1，既有消费者无需改动；并新增 `dense_field_matches_sparse_cells` 门槛逐格比对，Phase 1 当年的两个坑（时间轴丢空帧、无效值写 0）都被显式处理。

## 七、Phase 2 真正新增的东西：证据规则

这部分最初没有专门设想，但回看是 Phase 2 最有价值的产出。它的共同目的是：**让"看起来通过了"和"真的通过了"无法混为一谈。**

| 规则 | 防的是什么 | 它抓到过的真实问题 |
| --- | --- | --- |
| 阈值台账 | 指标算了、打印了，但没人比较 | K1 冻结前：两种真实失败被报成通过 |
| 字段裁决 | 规格声明了一个求解器从不读取的字段 | `max_depenetration_velocity_mps` 曾标为生效，实际从不生效 |
| 力控三道天花板 | 一个被声明却无人核验的数字 | 照搬 Phase 1 的 `force_ki` 会停在 0.75 N、0/1200 帧进容差带、20 s 超时中止 |
| 实测驱动上限 | 闭式校验描述的是理想驱动 | 阻尼 30/s 时静态检查报 1.5 N，内核实际只给 0.75 N |
| 比例稳定性 | 可用增益随输出步长变化 | `force_kp = 0.2` 在 60 Hz 稳定，在 120 Hz 持续振荡 |
| 时长与比例分离 | 比例不等于时长 | 只保持 1 帧（0.0167 s）能通过声明为 1 s 的要求 |
| 运行/里程碑分离 | 把一次 CPU 参考运行当成完整里程碑 | 索引里 `acceptance_passed: true` 与计划待办并存 |
| 两遍运行 | 把反馈产生的命令伪装成预先计划 | — |
| 哈希绑定 | 产物与结论脱钩 | — |

这九条里有六条是**在实现过程中被真实问题逼出来的**，不是预先设计的。记在这里是因为它们构成 Phase 2 可继承给 Phase 3 的主要资产之一——比任何单个模型都更难重建。

## 八、下一步

按依赖顺序，不按难度：

1. **Isaac Sim 适配器与有效参数采集** — K2 唯一剩余交付物。这一步完成前，"解耦"只有架构结论没有等价结论。需要一台装有 Isaac Sim 的 GPU 机器。
2. **K2 冻结提交** — 适配器落地后收口。
3. K3 多探头与分辨率 → K4 材料接触区域（层 3 第一次有真实内容）→ K5 Unity 与硬件。

**对照最初路线要补的一句：** 原始阶段一的"三种材料 + 振动双输出"要到 K4（材料响应）与 K5（多通道）才真正开始。当前位置更准确的描述不是"阶段一完成了多少"，而是"阶段一的地基已经打完，阶段一本身还没动工"。地基包括：冻结的证据契约、平台无关的接触内核、五层骨架、九条由代码强制的证据规则。这是原计划里没写、但事后看必须先有的东西。
