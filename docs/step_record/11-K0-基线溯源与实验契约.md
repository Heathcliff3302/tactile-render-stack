# K0：基线溯源与实验契约

## 目标

在写任何 Phase 2 代码之前，先把 Phase 1 **声明过的参数**变成不可篡改的输入，并为"一次运行是否算数"定义机器可校验的格式。

```text
Phase 1 源码（9 个文件）
→ 溯源规格 ×5（含 SHA-256）
→ 派生 CPU 参考规格 ×2
→ Schema ×3（InteractionState v2 / ExperimentSpec v1 / ExperimentManifest v1）
```

## 设计意义

Phase 1 的证据格式是 **CSV 列约定**——人读得懂，机器不校验。跨阶段比较时这不够：Phase 2 要声称"换一个后端，层 3–5 无需改动"，就必须有一个东西能判定"这一帧记录合不合法"，而不是靠读者对列名的印象。

更重要的是**溯源与派生分离**。Phase 1 的参数（例如 `max_press_speed_mps = 0.25`）在新内核上未必成立，但不能因此去改 Phase 1 的声明——那等于伪造历史。K0 因此确立一条规则，它在后续每个里程碑都被用到：

> **溯源记录不修改，提升发生在派生侧。**

## 三个被冻结的契约

| 契约 | 版本 | 作用边界 | 关键内容 |
| --- | --- | --- | --- |
| `InteractionState` | v2 | 层 2 → 层 3，"开放边界"所在 | 逐帧接触记录：几何、力、冲量、运动学、区域、可用性标记 |
| `ExperimentSpec` | v1 | 运行前规格 | 世界、运行时、控制器、采样、`acceptance` 阈值台账、字段裁决 |
| `ExperimentManifest` | v1 | 运行后清单 | 绑定条件、观测量定义、每个产物的 SHA-256 |

契约的机器校验规则以 `Phase_2/tactile_contract/schemas/` 为准，设计说明在同目录的 `*-v1.md` / `*-v2.md`。

## 规格的三类状态标记

每个参数值都要回答"它从哪来"，这三个取值是 K0 定义的：

| `status` | 含义 |
| --- | --- |
| `source_explicit` | Phase 1 源码里显式写出的值 |
| `unresolved` | PhysX 默认值，未经解析，不断言 |
| `design_choice` | Phase 2 自己选的值，并说明为什么 |

CPU 参考的重力 `9.81`、零摩擦、零恢复、零阻尼、零接触偏移都是 `design_choice`，**不是对未解析 PhysX 默认值的断言**。这个区分在 K1 的运行时字段裁决里被再次使用，两者正交：`status` 说值从哪来，裁决说内核是否据此行动。

## 实际结果

```text
溯源规格      5 个，覆盖 Phase 1 的 9 个源文件，各带 SHA-256
派生规格      2 个（k1_single_probe_cpu / k2_force_cpu，标记 cpu_reference）
Schema        3 个
比较 profile  1 个
```

`scenarios/build_k0.py` 里唯一出现 `isaacsim` 字样的位置是一个**路径字符串**，用于从 Phase 1 源码提取参数并记录哈希——不是 import。这是 Phase 2 全仓对 Isaac Sim 零 import 的边界条件。

## 验收结论

K0 通过。它交付的不是功能，而是后续所有里程碑的**判定依据**：没有 K0 的 Schema 和溯源规格，K1 的"十项门槛全通过"就只是一句自述。

## 边界与欠缺

- 只冻结了层 2 这一条边界。层 3/4/5 仍是进程内接口（见 [[10-Phase2总推进]] 的契约冻结账）。
- 溯源规格记录的是 Phase 1 **声明过**的值，不是 PhysX **实际生效**的值。后者需要在装有 Isaac Sim 的机器上采集，属 [[20-后续待办清单]] 的 B1。
- `unresolved` 的条目至今未解析。在那之前，两个后端之间只能做趋势比较。
