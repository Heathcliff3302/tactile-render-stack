# Phase 2 证据规则与护栏

这部分最初没有专门设想，但回看是 Phase 2 **最有价值的产出**。它们由代码强制，不是风格约定。共同目的只有一个：

> **让"看起来通过了"和"真的通过了"无法混为一谈。**

九条里有**六条是在实现过程中被真实问题逼出来的**，不是预先设计的。记在这里是因为它们构成 Phase 2 可继承给 Phase 3 的主要资产之一——比任何单个模型都更难重建。

## 九条规则

| 规则 | 防的是什么 | 它抓到过的真实问题 |
| --- | --- | --- |
| 阈值台账 | 指标算了、打印了，但没人比较 | K1 冻结前：两种真实失败被报成通过 |
| 字段裁决 | 规格声明了一个求解器从不读取的字段 | `max_depenetration_velocity_mps` 曾标为生效，实际从不生效 |
| 力控三道天花板 | 一个被声明却无人核验的数字 | 照搬 Phase 1 的 `force_ki` 会停在 0.75 N、0/1200 帧进容差带、20 s 超时中止 |
| 实测驱动上限 | 闭式校验描述的是理想驱动 | 阻尼 30/s 时静态检查报 1.5 N，内核实际只给 0.75 N |
| 比例稳定性 | 可用增益随输出步长变化 | `force_kp = 0.2` 在 60 Hz 稳定，在 120 Hz 持续振荡 |
| 时长与比例分离 | 比例不等于时长 | 只保持 1 帧（0.0167 s）能通过声明为 1 s 的要求 |
| 运行/里程碑分离 | 把一次 CPU 参考运行当成完整里程碑 | 索引里 `acceptance_passed: true` 与计划待办并存 |
| 两遍运行 | 把反馈产生的命令伪装成预先计划 | — |
| 哈希绑定 | 产物与结论脱钩 | — |

## 四条贯穿全仓的证据原则

### 不可用就是不可用

内核没有的量标为 `unavailable`，**绝不写入伪造的零**。刚体点接触没有物理接触面积，于是 `physical_contact_area_m2` 全程为空，而不是 0。

`null` 与 `0` 在这套契约里语义不同，写零会被下游当成真实测量。

这一条在 K2 反向修正了 Phase 1 的一处做法：Phase 1 在曲率或方向无效时写 `0.0`，使"未定义"与"平坦"无法区分。

### 每个观测量一个计算方法

方法名在整轮运行中恒定，并与实验清单绑定；适配器与清单读同一张表，不会互相偏离。

### 面积分层标注

占格代理、扫过路径、几何投影、模型接触面积是**四种不同的东西**，同帧分别输出，各带方法名。压力由占格代理导出时，方法名和语义说明都会讲清它随分辨率变化。

### 求解器与采样分开可见

求解器做了什么（`solver_contact`、`solver_normal_impulse_ns`）和采样报告了什么（`normal_force_n`）是两件事，都要能看到。采样阈值因此在力控回路**内部**，不是回路外的后处理。

## 阈值台账：结构性修复的样板

补门槛只修好今天。K1 的结构性修复是 `ACCEPTANCE_KEY_GATES` 与 `DEFERRED_ACCEPTANCE_KEYS` 两张台账：

> 规格 `acceptance` 块的每个键，**要么被某个门槛消费，要么是被显式声明的延后项**；有键落在两者之外时 `acceptance_key_ledger` 直接报错。

`all_passed` 还要求 `RUN_GATE_ORDER` 中的每一项都已发出：**缺失的门槛不能被读成通过**。

所有结论由唯一的 `finalize_report` 计算——调用方追加门槛后必须经它收口，不能自己写一遍 `all(gate["passed"] ...)`，那正是丢掉完整性要求的写法。

K2 把台账**双向化**：力控规格必须声明 `force_pass_fraction_min`，轨迹规格声明它则报错。

## 阈值的唯一归属

一个声明两次的容差可以和自己不一致。因此：

- 力控门槛读 `controller.force` 里的 `target_force_n`、`force_tolerance_n`、`settle_frames`，**不在 `acceptance` 里重复声明**。
- `hold_time_s` 与 `slide_time_s` 从 `controller.parameters` 读取。
- `acceptance` 只新增真正没有归属的阈值。

## 溯源与派生分离

**溯源记录不修改，提升发生在派生侧。**

Phase 1 声明的 `min_slide_force_in_tolerance = 0.9` 只存在于 `source_arguments`，按阈值台账的规则没有任何门槛能读到它。K2 在**派生的 CPU 参考**里把同一个值以 `force_pass_fraction_min` 写入 `acceptance`，溯源记录本身保持原样。

改动 `step6_force_64.json` 等于伪造 Phase 1 声明过的值。

## 自指禁令

**哈希绑定的文件不能包含关于自身哈希的已验证结论。** 稠密场本身就是被哈希绑定的产物之一，因此 `acceptance.json` 刻意少两项并在 `replay_gate_location` 说明它们在 `replay_check.json`。

## 加载期拒绝，而不是报告里备注

反复出现的同一条判断：**报告里的一行备注拦不住一次错误运行。**

| 校验 | 位置 | 拒绝什么 |
| --- | --- | --- |
| 字段裁决 | `runtime_policy.py` | 未分类字段、`recorded_inert` 字段的非惰性取值、`single_implementation` 的未实现取值 |
| 力目标可达性 | `drive_limits.py` | 目标加容差超出自身声明的压入上限（恰好只够到目标也拒绝） |
| 积分权限 | `drive_limits.py` | `force_ki × I_lim` 不足以在稳态维持目标命令 |
| 比例稳定性 | `drive_limits.py` | `mass × force_kp / output_dt ≥ 0.9` |
| 实测驱动上限 | `authority_probe.py` | 真实内核在声明上限下给不出目标力 |
| 命令出口限幅 | `controllers.py` | 越界的初始滑动速度（加载期）；开环分支同样受出口约束 |

## 必须失败的用例

PI 稳定性扫描包含一个**必须失败**的用例（`force_ki = 40`），用来证明这些断言确实能失败；还有一个用例直接验证实测边界与推导边界一致。

一组永远通过的断言和没有断言是一回事。

## 这套规则的盲区

全部九条规则验证的都是**代码与自己一致**。它们能防止代码退化、防止参数谎报、防止结论与产物脱钩，但它们**不能判断方向对不对**——因为没有一条规则需要与仓库外面的测量比对。

补上这个盲区是 [[20-后续待办清单]] A 组的全部内容。
