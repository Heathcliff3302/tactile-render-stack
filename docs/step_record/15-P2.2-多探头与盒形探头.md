# P2.2：多探头与盒形探头

## 目标

打破 K1/K2 的"单球探头、单个接触 Cell"假设，验证 Patch 的拆分、合并与 ID 稳定性。对应 Phase 1 的 [[06.5-多接触多网格多Patch]]。

| 子项 | 内容 | 状态 |

## P2.2.1 盒形探头（2026-10-28）

运行：`python -m mechanics.run_k3`。

盒形探头的总法向力按覆盖面积分配到 footprint 覆盖的每个 Cell，份额经过归一化，所以总力守恒是精确的。分配方法记为 `box_uniform_area_weighted_proxy`。

| 判据 | 结果 |
| --- | --- |
| 多个 Cell 同时接触 | ✓ |
| Cell 数随分辨率增长 | 64 / 196 / 676 |
| 总力不随分辨率变 | 三档都是 1.44 N |
| 几何面积不随分辨率变 | 三档都是 0.01 m² |
| 反证：探头抬高到 1.2 m | 无接触 ✓ |

**这个分配是声明过的近似，不是物理。** 刚性平底压在弹性半空间上，边缘压力是奇异的，而均匀分配把边缘算小了。反证用例原本断言"每个 Cell 载荷相等"，实跑测出 max/min = 6.25，原因是边缘 Cell 只被部分覆盖，份额也按覆盖率缩小。这一点写进了 `area_layers.note`。

范围限定：`run_k3` 直接驱动内核，没有经过五层环。所以在 10-28 时，盒形探头**在内核里成立，在链路里还不存在**。

## P2.2.2 多探头（2026-11-04）

运行：`python -m mechanics.run_k3_multi`。

- `mechanics/multi_probe.py`：一个内核里放多个探头，每个探头配一台独立的 `TrajectoryStateMachine`，各读各的延迟反馈；层 2–5 每条流各一套。
- 每条流都是一次完整的 K1 运行，K1 的写盘、稠密场、回放代码原样复用。
- 三项跨流门槛（`validation/multi_acceptance.py`）：
  - `streams_are_independent`：每条流和该探头单独跑时逐帧相等；
  - `patch_ids_are_stable`：沿用 Step 6.5 对主 Patch、边缘 Patch 的定义；
  - `box_streams_activate_multiple_cells`：盒形流在 hold 段要跨两个及以上格子。
- `patch_coverage_min` 在多探头台账里被消费，不再挂账。

**状态**：代码和测试都在，测试全部通过；但验收文档 `plans/2026-11-04-P2.2.2-P2.4-验收.md` 一直没有经过用户审阅。2026-11-25 用户决定 Isaac 比对不包含盒形探头。所以它的状态是**已实现、未验收、未与 Isaac 比对**。

## 留下的结论

1. **多点接触的力分配，是层 2 与层 3 的分界问题。** 均匀分配只是层 2 的近似，真实分布要靠层 3 的模型给出。Phase 3 由数据学出的映射模型回答这个问题。
2. **"在内核里成立"和"在链路里成立"要分开说。** P2.2.1 的日志一开始没写清楚这个范围，11-03 回顾时才补上。
