# P2.4：IMU 纹理频谱（只有分析侧）

## 目标

2026-10-28 曾把 P2.4 定为外部参照的主线：用现成的微振 IMU 划过三档砂纸，检验 `f = v/λ`。速度翻倍时纹理峰频率也应翻倍，而装置共振不随速度变，这是区分真假信号的判据。

## 做了什么（2026-11-04）

代码在 `validation/imu_spectrum/`：

- 频带定义只有一份，和以后的 P2.7.1 振动谱通道共用；
- 会话清单格式（`session_template.json`），不合格的会话在加载时就被拒绝；
- Welch 功率谱、频带功率、扣除空白对照；
- 按砂纸目数排序的检验，以及 `f = v/λ` 的速度比对照表。

## 为什么停了

1. **一直没有采集。** IMU 用 SPI 还是 I²C、能不能逐样本打时间戳，这个问题悬了 7 天以上。400 kHz 的 I²C 撑不住约 46 KB/s 的数据率。
2. **主线变了。** 11-05 外部参照改用公司的视触觉硬件；11-09 确立核心命题（具身与虚拟潜行的反映射）；11-13 起转向 Phase 3。
3. **复盘结论**：当初选 IMU，只因为它最便宜、现在就能做，并不是因为振动通道最重要。依赖链 P2.4 → P2.7 → P2.8 → P2.6 把层 4、层 5 都排在了一次振动采集后面。这是规划上的过拟合：挑了最便宜的参照，而不是最相关的参照。

## 去向

作为**振动支线**保留，不阻塞任何一条主线。公司指尖的力传感器约 62 Hz、图像约 25 帧/秒，覆盖不了纹理振动，所以以后需要振动真值时，这份分析代码可以直接接回来。

**规则**：数据只能由用户采集，akio 不得生成或估计频谱数据。
